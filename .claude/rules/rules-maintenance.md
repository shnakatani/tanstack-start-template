# rules 更新ルール

## 原則

rules は実装時に引く規範を置く。
「なぜそう決めたか」は ADR、「いつ何を変えたか」は git 履歴が持つ (ADR-0001)。

判定は `doc-hygiene.md` に従う。
ここは rules 固有の書き方を持つ。

## 1 項目に書くもの

- 規範 (何をするか、何を禁じるか)。禁止を書くときは正解を対で書く
- 理由 1 文 (守らないと何が壊れるか)
- 出典キー 1 つ (ADR 番号、仕様の条項番号、上流 issue 番号のいずれか)
- 選択肢に順序があるならその順序 (先に試すもの、最終手段)
- 打ち消し不能または検出不能な落とし穴 (破っても静かに壊れるもの)

## 書かないもの

- 実測値の詳細 (違反件数、実測した px 値、所要時間)。根拠の実測は ADR へ置く
- 選択肢の比較と却下理由
- 改訂履歴 (「いつ何を変えたか」)
- 出典の解説文 (条項番号があれば仕様書を引ける)

これらは ADR に書く。ADR が無い主題なら出典キーだけ残す。

## 何が規範に当たるか

手順、選択肢の順序、具体的な組み立て方、打ち消し不能の落とし穴、適用範囲の確定は、いずれも規範であって理由ではない。

## サイズ

- 1 項目 (箇条書き 1 つ、または表の 1 セル) は 200 字以下。超えたら根拠が混ざっている (ADR-0001)
- ファイル全体の行数に上限は設けない。1 行ずつ `doc-hygiene.md` の判定を当て、No なら削る (ADR-0001)
- 規約があるのに繰り返し破られるなら、ファイルが長すぎて規則が埋もれている兆候 (ADR-0001)
- 主題が複数混ざったら分割する

文字数は改行を除いて数える。表は前後の空白と `|` 区切りを除いたセル本文で数える。`awk` の `length()` は BSD awk がバイトを返すため使わない (ADR-0001)。

測るときは表をセルへ分解し、コードブロックは飛ばす。行のまま測ると整形の桁揃えを含む幅で偽陽性が出て、コードブロックを含めると規範でない行を拾う。

このコマンドはフェンスの開閉を区別しないため、行頭のフェンス行が奇数のファイルでは以降を無言で測らない。入れ子のフェンスがあると偶数でも誤検出しうる。先にフェンス行を数えて、奇数なら結果を信じない。

````bash
perl -CSD -ne 'if (/^```/) { $fence = !$fence; next } next if $fence;
  chomp; next if /^\s*\|[\s:|-]+\|\s*$/;
  for (/^\s*\|/ ? grep { length } map { s/^\s+|\s+$//gr } split /(?<!\\)\|/ : $_) {
    printf "%3d: %5d\n", $., length($_) if length($_) > 200 }' <file>

grep -c '^```' <file>   # 奇数ならフェンスが閉じていない
````

## 構造

- 対象の種別で対応が決まる規範は表で書く。箇条書きより引きやすい
- 同じ主題を離れた項目に分散させない

## 参照のされ方

`src/` や `scripts/` のコメントと ADR が rules を見出し語で指す。
見出し語を変えるときは `grep -rn "<旧見出し語>" src/ scripts/ docs/ .claude/` で参照側も更新する。
番号 (「例外 4」) で参照させない。番号は編集でずれ、ずれても静かに壊れるだけになる。
