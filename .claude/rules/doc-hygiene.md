# ドキュメント作法

ドキュメントを書くときと変えるときに共通で効く規範。
PR 本文はファイルを持たないため、同じ規範を常時ロードの `pr.md` が持つ。
媒体にしかない制約は `agents-md-maintenance.md` / `rules-maintenance.md` / `docs/decisions/README.md` が持つ。

## 置き場所と削除の判定

- 規範は `.claude/rules/`、決定の経緯は `docs/decisions/`、いつ何を変えたかは git 履歴が持つ (ADR-0001)
- 書くか削るかは、それが無いと実装者が誤った選択をするかで判定する。するなら、それは理由ではなく規範として残す (ADR-0001)

## 1 つのドキュメントの中

- チャット内の参照 (`[Image #N]`) を残さない。文章で言い換える (ADR-0001)
- 指示語を残さない。「本 PR」「今回の」は PR 番号か日付か commit hash に置換する (ADR-0001)
- 相対日付を書かない。`YYYY-MM-DD` へ変換する (ADR-0001)
- 追加一方にしない。編集のたびに統合と削除も検討する (ADR-0001)
- このリポジトリのコードや作業で動く数値 (違反件数、該当箇所数) は書かない。測り方だけ残す (ADR-0001)
- 外部の一時点の観測 (上流ツールの挙動、計測環境) は、日付とバージョンを添えて書く。後で変わったとき、いつの観測か判別できる (ADR-0001)
- 判断の根拠を兼ねる数値は、日付を添えて書き、後から消さない。消すと論証が成立しなくなる (ADR-0001)
- 数値は rules と AGENTS.md ではさらに厳しい。制約は `rules-maintenance.md` と `agents-md-maintenance.md` が持つ (ADR-0001)

## ドキュメントの間

- 他ドキュメントの文言を引用しない。文書の番号や見出しで指す。引用元が書き換わると引用が宙に浮く
- ADR は `ADR-NNNN` の文書番号で指す。項目の序数 (「例外 4」) では指さない。markdown リンクを張るのは `docs/decisions/README.md` の一覧と `Superseded-by` 行の補助リンクだけ
- 決定を別の文書へ移すとき、移した先が覆した内容を自分の言葉で持つ。旧側の書き換えだけでは根拠が git 履歴にしか残らない
- 同じ結論の記述が複数の文書にあることは許す。禁じるのは、一方だけを読んだ人が反対の結論に至る状態 (ADR-0001)
- 陳腐化したポインタは注記を足さず、文ごと削除する
- spec と plan は作業完了後に当時の記録として凍結し、ADR や rules と食い違って見えても書き換えない。書き換えると、その時点で何を根拠に決めたかが読めなくなる
