# ADR-0001: ドキュメントを規範と経緯と履歴の 3 層に分ける

- Status: Accepted
- Date: 2026-08-17
- 関連: ADR-0000 (ADR の改訂と置き換えの扱い) / ADR-0004 (コメントは ADR を指す) / ADR-0002 (rules の 1 項目に書くもの) / ADR-0003 (読み込まれる契機で置き場所を決める)

## Context

`.claude/rules/` は Claude が作業中に読み込む規範を置く場所である。
決定の根拠と改訂履歴を同じ行へ足していくと、規範 1 個に出典と派生規範と履歴が同居した長い項目に育つ。
実装時に必要なのは規範だけだが、取り出すには全文を読むしかない。

作法そのものを媒体ごとのファイルが各自で持つと、同じ規範が複数箇所へ写される。
片方だけを直したとき、どちらが現在の規範かを読み手が判断できなくなる。

## Decision

### 置き場所

| 置き場所          | 持つもの                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------- |
| `.claude/rules/`  | Claude が作業中に読み込む規範と理由 1 文。コードや ADR からは参照しない                                       |
| `docs/decisions/` | 決定の経緯、選択肢比較、実測値                                                                                |
| git 履歴          | いつ何を変えたかの記録。ADR の枠内の改訂 (`Revised`) と置き換え (`Superseded`) は ADR 自身にも残す (ADR-0000) |

参照は一方向にする。rules は根拠として ADR を指し、ADR とコードは rules を指さない (コードの側の決定は ADR-0004)。rules は作業中に読み込ませるための規範で、利用者が自分のプロジェクトに合わせて書き換えるので、根拠の側が rules に依存すると参照先が消える。

### 作法の層

ドキュメントの書き方そのものは、下の層が上の層を目的に照らして選別し、この媒体へ再編集して持つ。

| 層         | 置き場所                             | 持つもの                                  |
| ---------- | ------------------------------------ | ----------------------------------------- |
| 原型       | 開発者個人の環境                     | 媒体非依存の原則                          |
| リポジトリ | `.claude/rules/docs.md`              | このリポジトリでの書き方                  |
| 媒体固有   | `.claude/rules/docs.md` の媒体別の節 | その媒体にしかない制約 (rules・AGENTS.md) |

リポジトリ層を置くのは、個人環境の設定が他の開発者の手元では読み込まれないためである。
作業の進め方の規範 (整理の範囲確定、修正の動機の記録) はドキュメントの書き方ではないので、リポジトリ層に持ち込まない。

同じ結論の記述が層をまたいで存在することは許す。
禁じるのは、一方だけを読んだ人が反対の結論に至る状態である。

### 数値の階層

| 媒体           | 数値の扱い                                                                 |
| -------------- | -------------------------------------------------------------------------- |
| ADR / 解説文書 | コードで動く数値は書かない。外部の一時点の観測と判断の根拠は日付つきで書く |
| rules          | 実測値の詳細を書かない。根拠の実測は ADR へ                                |
| AGENTS.md      | 判断を決める閾値だけを書く                                                 |

### 検討した選択肢

| 案                                 | 評価                                                       | 採否     |
| ---------------------------------- | ---------------------------------------------------------- | -------- |
| 作法をリポジトリ層に再編集して持つ | 他の開発者の手元でも読み込まれ、原型との二重管理にならない | **採用** |
| 作法を原型から写す                 | 個人環境と同時ロードされ、二重管理になる                   | 却下     |
| 作法を個人環境だけに置く           | 他の開発者に届かない                                       | 却下     |

## Consequences

- 原型とリポジトリ層は別リポジトリにあり相互参照を張れない。ドリフトは避けられないが、リポジトリ層が出典を持つのでどちらが古いかは判別できる
- ADR を書き換えるときの扱い (枠内の改訂は `Revised`、決定の置き換えは `Superseded`、実測値の追記や表現の補足は `Revised` に載せない) は ADR-0000 が持つ
