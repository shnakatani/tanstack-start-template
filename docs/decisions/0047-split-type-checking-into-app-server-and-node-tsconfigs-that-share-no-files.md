# ADR-0047: 型検査の tsconfig を app・server・Node の 3 つに分け、どのファイルも 1 つにだけ入れる

- Status: Accepted
- Date: 2026-11-24
- 関連: ADR-0010 (実行環境をファイル名の接尾辞で宣言し、実行時の境界は `importProtection` が持つ)、ADR-0038 (`lib` の `ESNext.Error`)

## Context

`vp check` は、oxlint の type-aware の経路 (tsrs) で型検査を行う (`docs/guides/dependencies-and-toolchain.md`「`typescript` を直接の依存に置かない理由」、`tooling/lint/config.ts` の `typeCheck: true`)。
2026-11-23 に vite-plus 1.7.0 の tsrs 7.1.0-beta.tsrs2 で probe すると、tsrs は、ファイルを `include` に持つ tsconfig の program でそのファイルを検査し、import で別の program に入っただけのファイルは、その program では検査しなかった (`src/server/` のファイルの `document` は TS2584 になり、`document` を使う `src/lib/` のファイルを `src/server/` から import しても TS2584 は出なかった)。

このテンプレートのファイルは、動く環境で 3 つに分かれる。

| 動く環境          | ファイル                                                                                                                    | 区分の出典                                                                                                                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ブラウザと SSR    | `src/` のうち、次の行に当たらないもの。そのテストと story も同じ行に数える (テストは Node かブラウザのテストランナーで動く) | TanStack Start docs「Execution Model」の "**All code in TanStack Start is isomorphic by default** - it runs and is included in both server and client bundles unless explicitly constrained." |
| サーバーだけ      | `src/server.ts`、`src/**/*.server.ts`、`src/**/*.server.tsx`、`src/server/`                                                 | ADR-0010。環境は接尾辞で宣言する。`src/server/` はドメインに属さない server の基盤 (DB の接続とテーブルの定義など) を置き、横断的な server function の宣言も置ける                            |
| Node (開発の道具) | `scripts/`、`tooling/`、`vite.config.ts`、`drizzle.config.ts`、`.storybook/main.ts`                                         |                                                                                                                                                                                               |

型の境界と bundle の境界は、別の import の連なりで引かれる。

- bundle では、TanStack Start のコンパイラが client の build で `createServerFn()` の handler を RPC の stub に置き換え、handler だけが使っていた server の import を外す (docs「Import Protection」の "when the compiler replaces a `createServerFn()` handler with a client RPC stub, it can also remove server-only imports that were only used by the removed implementation.")。import protection は build では tree-shaking の後に判定する ("In **build mode**, import protection defers violation checks until after tree-shaking.")
- 型検査は、置き換える前の import を辿る。2026-11-03 に TypeScript 6.0.3 の `tsc --explainFiles` で見ると、DB を引く server function が 1 つでもあれば、server function を宣言するファイル (`src/features/<domain>/functions.ts`) から `handlers.server.ts`、`src/server/db/index.ts` を経て DB の driver の型 (`@types/better-sqlite3` 9.6.0 の `/// <reference types="node" />`) が入り、ブラウザの program に Node の型が入っていた。サンプル実装を消した直後のテンプレートには DB を引く server function が無く、この連なりも無い
- docs「Execution Model」の「Module-Level `process.env` Reads」は、`createServerFn().handler()` の中で `process.env` を読む形を正しい形 (✅) として示す。この形のファイルはブラウザの program に入る

公式の案内は 2 つの向きがある。

| 出典                                                                                        | tsconfig の形                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TanStack Start の docs「Build from Scratch」「Path Aliases」                                | ルートの `tsconfig.json` に設定を書く形を示す。`references` の記述は無い                                                                                                                                                                                       |
| TanStack/router の `examples/react/start-*`                                                 | `tsconfig.json` を持つ 22 本はどれも `tsconfig.json` 1 本だけで、`tsconfig.*.json` は 0 本 (main `f723f3b8be` の git tree を `^examples/react/start-[^/]+/tsconfig\.[^/]+\.json$` で数えた。2026-11-03)                                                        |
| TanStack CLI の雛形 (`packages/create/src/frameworks/react/project/base/tsconfig.json.ejs`) | `include: ["**/*.ts", "**/*.tsx"]`、`lib` に `DOM`、`types: ["vite/client"]` (Vite のとき) の 1 つ (TanStack/cli main `270f9b06fd`、2026-11-03)                                                                                                                |
| create-vite の react-ts (vitejs/vite main `b3cb0575af`)                                     | ルートは `files: []` と `references` だけで、`tsconfig.app.json` (`src`、`lib` に DOM) と `tsconfig.node.json` (`vite.config.ts`、`types: ["node"]`) に分ける。動機は vitejs/vite#15913 の "`tsc` doesn't fail when there are type errors in `vite.config.ts`" |
| TypeScript の handbook「Project References」の「Guidance」                                  | 共通の `compilerOptions` は継承の元の 1 つの tsconfig に置く。ルートは `references` と空の `files` だけにする ("otherwise the solution file will cause double compilation of files")                                                                           |
| Vite docs「Shared Options > tsconfig」                                                      | `tsconfig` option を設定しないよう勧める警告の中で "Prefer placing a `tsconfig.json` near the files it configures and using TypeScript references for multi-project setups." と書く                                                                            |

## Decision

**型検査の tsconfig を app (ブラウザと SSR)・server (サーバーだけ)・node (Node) の 3 つに分け、ルートの `tsconfig.json` の `references` でつなぐ。どのファイルも 3 つのうち 1 つの `include` にだけ入れ、重なりは app の `exclude` で無くす。**

| ファイル               | 中身                                                                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tsconfig.base.json`   | 共通の `compilerOptions`。`paths` (`@/*`) と、DOM を持たない `lib` (`ES2024`、`ESNext.Error`) を持つ                                                                                                                            |
| `tsconfig.json`        | `extends: "./tsconfig.base.json"`、`files: []`、`references` (app・server・node)                                                                                                                                                |
| `tsconfig.app.json`    | `include` は `src/**/*.ts`・`src/**/*.tsx`・`.storybook/preview.tsx`、`exclude` は server の `include` と同じ範囲。`lib` に `DOM` と `DOM.Iterable`、`types` は `vite-plus/client`・`vite-plus/test/browser-playwright`・`node` |
| `tsconfig.server.json` | `include` は `src/server/**/*.ts`・`src/server/**/*.tsx`・`src/server.ts`・`src/**/*.server.ts`・`src/**/*.server.tsx`。`lib` は base のまま、`types: ["node"]`                                                                 |
| `tsconfig.node.json`   | `include` は `scripts/**/*.ts`・`tooling/**/*.ts`・`vite.config.ts`・`drizzle.config.ts`・`.storybook/main.ts`。`lib` は base のまま、`types: ["node"]`                                                                         |

1. 重なりは `exclude` で無くす。`references` の並び順に意味を持たせない。どのファイルも `include` で持つ tsconfig が 1 つに決まるので、`vp check` と `tsc -p <tsconfig>` で、ファイルを根に持つ program が食い違わない (並び順で割り当てる案の却下の理由は「検討した選択肢」)
2. テストと story は app に入れる。`src/server/` の下のテスト (`src/server/db/index.test.ts` など) だけが server に入り、`*.server.ts` の横に置くテストは `src/**/*.server.ts` に当たらないので app に入る。テストが `declare module` を持つファイル (`src/lib/page-name.ts` など) と同じ program に入るので、型を補う宣言のファイルは要らない
3. app の `types` に `node` を書く。app の単体テスト (`src/**/*.test.ts`) は Node で動き、`node:vm` と `process.env` を使う (`src/lib/server-error-exposure.test.ts`、`src/test/test-time-zone.tz.test.ts`)
4. ルートの `tsconfig.json` は base を `extends` して `paths` を持つ。shadcn の CLI はルートの `tsconfig.json` の `paths` だけを読む (shadcn-ui/ui#11466 "tsconfig.app.json tsconfig.node.json are ignored"、fallback を足す shadcn-ui/ui#11469 は 2026-11-03 時点で open)。`vp exec shadcn info` の `importAlias` は、この形で `@`、`extends` を外すと `-` だった (2026-11-03、shadcn 4.22.2)
5. `composite` は書かない。この形で `vp dlx -p typescript@6.0.3 tsc -b` は exit 0 だった (2026-11-03)。create-vite の react-ts も、空のルートから参照する形では `composite` が要らないとして外している (vitejs/vite#17774)

`vp check` での境界は次のとおりである (probe を置いて `vp check --no-fmt` を打ち、probe は消した。2026-11-23、vite-plus 1.7.0)。

| probe を置いた場所 (program)                                     | 書いた式                                                                    | 結果                                                                                    |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `src/server/` (server)                                           | `document.title`                                                            | TS2584 `Cannot find name 'document'`、`no-unsafe-assignment`、`no-unsafe-member-access` |
| `src/lib/<name>.server.ts` を app のファイルから import (server) | `document.title`                                                            | 同上。app の program に import で入っても、server の program で検査される               |
| `src/server/` (server)                                           | `process.env.HOME`                                                          | 通る                                                                                    |
| `src/lib/` (app)                                                 | `Buffer.from("a").toString("base64")`、`process.env.HOME`、`document.title` | 通る。`Buffer.from("a")` を `number` に入れた行は TS2322 で、`Buffer` に型が付いている  |
| `scripts/` (node)                                                | `document.title`、`Buffer.from("a").toString("base64")`                     | 通る。`document.title` を `number` に入れた行は TS2322 で、`document` に型が付いている  |

app と node に境界ができない理由は、どちらも依存の型の連なりである (`vp dlx -p typescript@6.0.3 tsc -p <tsconfig> --noEmit --explainFiles`、2026-11-03)。

| program | 外せない型 | 入る連なり                                                                                                                                                                                                                                                                                                                                         |
| ------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| app     | Node       | story の型 (`@storybook/tanstack-react` → `@storybook/builder-vite` → Vite の Node 向けの型。story 1 本だけの program にも `@types/node` が入った)、ブラウザテストの型 (`@vitest/browser` → `vitest/node`)、`types` の `node`、DB を引く server function があればその driver の型 (Context)。`types` から `node` を外しても `@types/node` は残った |
| node    | DOM        | `scripts/contrast/` が使う `colorjs.io` 0.7.1 の型が `/// <reference lib="dom" />` を持つ                                                                                                                                                                                                                                                          |

### 型検査の実行

**型検査は `vp check` だけで見る。tsrs の README が勧める別の `tsrs --noEmit` は走らせない。** Vite+ docs「Check」(v1.7.0) は "We recommend turning both `typeAware` and `typeCheck` on so `vp check` becomes the single command for static checks during development." と書く。

- `vp check` の型検査は、lint の対象のファイルだけを検査する。lint の対象から外したファイルの診断は出ない。位置の無い global の診断は、同梱の tsrs 7.1.0-beta.tsrs2 では出ない (版で変わる。下の global の診断の項目) (tsrs の `tools/tsgolint/README.md`、v7.1.0-beta.tsrs2: "files oxlint does not lint (ignored, generated and declaration files) and global diagnostics are checked only by `tsrs --noEmit` or `tsrs --build`.")。この範囲は tsgolint のときから同じである (oxc-project/tsrs#998: "as tsgolint does")。同じ README は宣言ファイルも lint しないファイルに挙げるが、2026-11-25 に vite-plus 1.7.0 の tsrs 7.1.0-beta.tsrs2 で、`vp check` は `src/` の `.d.ts` を lint し、`skipLibCheck` を `false` にすると `vp check --no-fmt` は型の診断も出した (下の表の宣言ファイルの行)
- 2026-11-24 と 2026-11-25 に vite-plus 1.7.0 の tsrs 7.1.0-beta.tsrs2 で、lint の対象と tsconfig の program の差で見逃す型の誤りは無かった。差が出うるファイルとして、`ignorePatterns` で外すファイルと、tsrs の README が lint しないとする宣言ファイルを下の表に挙げる。どれも `tsc` でも型の誤りが報告されない。`tooling/lint/config.ts` の `ignorePatterns` が外す TS のファイルは、`src/routeTree.gen.ts` と `docs/registry-baseline/` だけである。確かめ方は、`git ls-files -co --exclude-standard` の TS のファイルを `ignorePatterns` と突き合わせることと、`docs/guides/dependencies-and-toolchain.md`「tsconfig にファイルを割り当てる」の手順を `':!docs/registry-baseline/**'` の除外を外して打つこと。2026-11-24 に打つと、どの tsconfig にも入らないファイルとして `docs/registry-baseline/` のファイルだけが出て、`src/routeTree.gen.ts` と `src/env.d.ts` は app の tsconfig の `--showConfig` の `files` にあった

  | ファイル                      | lint                        | tsconfig                    | `tsc` でも報告されない理由と実測                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
  | ----------------------------- | --------------------------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `src/routeTree.gen.ts`        | `ignorePatterns` で外す     | app の `include` に入る     | TanStack Router の generator が、既定で先頭に `// @ts-nocheck` を書く (TanStack Router docs「File-Based Routing API Reference」の `routeTreeFileHeader`)。`vite.config.ts` はこの option を変えていない。2026-11-24 に末尾へ TS2322 を置くと、`vp check`・下の段落の `tsrs -b`・`vp dlx -p typescript@6.0.3 tsc -p tsconfig.app.json --noEmit` のどれも通した。`// @ts-nocheck` の行を消すと、`tsrs -b` と `tsc` は TS2322 で落とし、`vp check` は通した                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
  | `docs/registry-baseline/`     | `ignorePatterns` で外す     | どの `include` にも入らない | どの program にも入らない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
  | 宣言ファイル (`src/env.d.ts`) | `ignorePatterns` で外さない | app の `include` に入る     | `tsconfig.base.json` の `skipLibCheck: true` で、`tsc` は宣言ファイルを型検査しない (TSConfig Reference「skipLibCheck」: "Skip type checking of declaration files.")。2026-11-25 に読んだ tsrs v7.1.0-beta.tsrs2 のソースでも、`skipLibCheck` が真なら宣言ファイルの型検査を飛ばしていた ([`skip_type_checking`](https://github.com/oxc-project/tsrs/blob/b12862d0636c21a98d53d01c6b29570ef5f604e7/crates/tsrs_compiler/src/program.rs#L1571-L1578))。同じ日に vite-plus 1.7.0 の tsrs 7.1.0-beta.tsrs2 と typescript 6.0.3 で、`src/` に `.d.ts` を置いて測った。型の誤り (TS2304・TS2717) だけを置くと、`vp check`・`vp dlx -p typescript@6.0.3 tsc -p tsconfig.app.json --noEmit`・下の段落の `tsrs -b` のどれも通した。`skipLibCheck` を `false` にすると、`vp check --no-fmt` と `tsc` は 2 つとも報告した。`skipLibCheck: true` のまま文法の誤り (TS1039) を足すと、`vp check` は fmt の段で止まり (Vite+ docs「Check」: "If formatting fails, `vp check` stops before lint and type checks run.")、`vp check --no-fmt` と `vp lint` は TS1039 だけを出し、`tsc` と `tsrs -b` は通した。`skipLibCheck` を `false` にした `tsc` と `tsrs -b` は 3 つとも報告した。`any` の型注釈を置くと、`vp lint` と `vp check` は `typescript(no-explicit-any)` を出した |

- 黙って見逃す既知の経路がある。同じ名前の `.ts` と `.tsx` が並ぶファイルと、`include` の外にあり import で tsconfig の program に入るファイルは、lint の型検査では推論した program で検査され、tsconfig の `compilerOptions` を落として型の誤りを見逃す。`tsrs --noEmit` は拾う (oxc-project/tsrs#1046、2026-11-24 に open)。後者は Consequences の、server の `include` と app の `exclude` の項目 (どの `include` にも入らないファイル) と同じ扱いである。2026-11-24 に `git ls-files -co --exclude-standard '*.ts' '*.tsx' | sed -E 's/\.tsx?$//' | sort | uniq -d` は何も出さなかった
- global の診断の扱いは、同梱の tsrs の版で変わる。7.1.0-beta.tsrs2 は報告せず、v7.1.0-beta.tsrs4 からは program ごとに tsconfig の上で報告する (oxc-project/tsrs#1056: "global diagnostics once per program, on its tsconfig and without a range, such as TS2318")。2026-11-24 に app の tsconfig の `types` へ参照されていない名前を足すと、`vp check` は型検査の TS2688 ではなく `typescript(tsconfig-error)` ("Invalid tsconfig"、help は "Cannot find type definition file for '<名前>'.") で落ち、`tsrs -b` は TS2688 で落ちた。同梱の tsrs が tsrs4 以降になったら、この結果を測り直す

| 案                                               | 今差が出るか      | 同梱の版とずれないか                                                                                                                                             | oxc-project/tsrs#1046 の見逃しを拾うか                                                                                                                                  | 採否     | 却下の理由                                                                                                                                                    |
| ------------------------------------------------ | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vp check` だけ                                  | 出ない (上の項目) | ずれない。`vite-plus` が入れる tsrs を使う                                                                                                                       | 拾わない                                                                                                                                                                | **採用** |                                                                                                                                                               |
| verify に `vp dlx -p tsrs@<版> tsrs -b` を足す   | 出ない            | 版を手で書くので、`vite-plus` を上げるたびに書き換える。書き忘れると、`vp check` と別の版で検査する                                                              | 拾う見込み。lint の経路を通らず、program のすべてのファイルを tsconfig の設定で検査する (issue が `tsrs --noEmit` は拾うとするのと同じ理由。`tsrs -b` では測っていない) | 却下     | 差が出ない今は、版を書き換える手間だけが増える                                                                                                                |
| `typescript` を直接の依存に戻し、`tsc -b` を足す | 出ない            | ずれる。typescript-eslint の `typescript` の peer が `<6.1.0` の間は 6 系に留まり (ADR-0023)、`vp check` の tsrs (TypeScript 7.1.0-beta 相当) と診断が分かれうる | 拾う見込み (同じ理由。`tsc -b` では測っていない)                                                                                                                        | 却下     | 診断が分かれうるうえ、`typescript` を直接の依存に置かない決定 (`docs/guides/dependencies-and-toolchain.md`「`typescript` を直接の依存に置かない理由」) を覆す |

別に型検査を走らせるのは、tsconfig の `include` に入り `// @ts-nocheck` を持たない TS のファイルを lint の対象から外すとき (生成した TS を `ignorePatterns` に足すときと、`routeTreeFileHeader` を変えたか TanStack Router を上げて既定が変わったかで、`src/routeTree.gen.ts` の先頭から `// @ts-nocheck` が消えるとき) と、同じ名前の `.ts` と `.tsx` を並べるときである。打つ形は表の 2 つ目の案で、版は `vp --version` の `tsrs` の行にする。Vite+ docs (v1.7.0) は同梱の tsrs を打つ形を案内せず、`vp exec tsrs` は `Command 'tsrs' not found in node_modules/.bin` で落ちる。2026-11-24 に、この形は誤りの無いツリーで exit 0、`src/lib/` に置いた TS2322 で exit 2 だった。`tsconfig.base.json` の `noEmit: true` でも `tsconfig.app.tsbuildinfo`・`tsconfig.node.tsbuildinfo`・`tsconfig.server.tsbuildinfo` を書く (`.gitignore` の `*.tsbuildinfo` で無視される)

## Consequences

- サーバーでだけ動くファイルで DOM の global を書くと、`vp check` が TS2584 で止める
- `src/server/` に置いた横断的な server function の宣言のファイルは、クライアントからも import されるが、server の program で DOM なしに検査される。宣言のファイルはサーバーの bundle にも入るので (Context)、そこで DOM の global を書けばサーバーで壊れる
- ブラウザで動くコードで Node の global を書いても、Node で動くコードで DOM の global を書いても、型検査は止めない。実行時に壊れる import は `importProtection` が `vp build` で止める (ADR-0010)
- server の `include` と app の `exclude` は同じ範囲を指し続ける。片方だけ変えると、ファイルが 2 つの tsconfig に入るか、どちらにも入らない。2026-11-23 に vite-plus 1.7.0 で確かめると、どの `include` にも入らないファイルも `vp check` は検査し、DOM の global を通したが、既定の設定には `paths` が無いので `@/` の import は TS2307 で落ち、Node の型も無かった。割り当ての確かめ方は `docs/guides/dependencies-and-toolchain.md`「tsconfig にファイルを割り当てる」にある
- リポジトリの直下にコードのディレクトリを足したら、3 つのどれかの `include` に足す
- 再評価条件: TanStack Start の docs か CLI の雛形が tsconfig を分ける形を示したとき。tsrs か TypeScript の docs が `references` の順でファイルを割り当てると定めたとき (`exclude` を外せる)。shadcn の CLI が `references` の先の `paths` を読むようになったとき (ルートの `extends` を外せる)
