# ADR-0033: ページのデータは Query から読み、欠かせない query だけを loader で待ち、副次的な query は待たずに Suspense の中で読む

- Status: Accepted
- Date: 2026-10-22
- 関連: ADR-0019 (一覧の絞り込み条件を loader に渡す)、ADR-0029 (既定の pending 表示)、ADR-0041 (既存の値を編集するダイアログの loader)

## Context

ページのデータを route の loader と TanStack Query のどちらから読むか、loader がその取得を待つかで、初めの HTML に何が入るかと、route の遷移がどこで止まるかが決まる。

## Decision

**ページのデータは TanStack Query が持ち、コンポーネントは loader の戻り値ではなく `useSuspenseQuery` で読む。loader は、ページの表示に欠かせない query の取得を待ち、副次的な query は待たずに流す。副次的な query は Suspense の境界の中で読む。同じ route に留まる読み込みでは、head の値・notFound・redirect・認可を決めない query に限り、欠かせない query も待たずに流す。ページの中の失敗は `SectionErrorBoundary` で区画の中に出す。**

| 対象                                                                                                                                | 書き方                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 欠かせない query (主要な中身・タイトル・認可・リダイレクト・存在を決める)                                                           | loader で `queryClient.query({ ...options, staleTime: "static" })` を await し、値は返さない。返すのは「route の `head` が要る値」の行の値だけにする。`staleTime: "static"` はキャッシュがあればそれを返し、取得し直しで待たない。同じ route に留まる読み込みの扱いは次の行                         |
| 同じ route に留まる読み込み (loader の `cause` が `"stay"`。検索条件・path params の変化、`router.invalidate()`、子 route から戻る) | head の値・notFound・redirect・認可を決めない query は待たずに `void queryClient.query(...).catch(noop)` で流し、読む部分を `<Suspense>` と `SectionErrorBoundary` で囲む。待つと失敗が route のエラーになり、条件を変えた欄 (検索欄など) ごとエラー表示に置き換わる。決める query は stay でも待つ |
| 副次的な query                                                                                                                      | loader で `void queryClient.query(options).catch(noop)` (`noop` は `@tanstack/react-query` の export) とし、読む側を `<Suspense>` と `SectionErrorBoundary` (`src/components/parts/section-error-boundary.tsx`) で囲む。reject を受けないと、失敗がサーバーで未処理の reject になる                 |
| route の `head` が要る値                                                                                                            | loader から返し、`head` で読む。コンポーネントは同じ値も `useSuspenseQuery` で読む                                                                                                                                                                                                                  |
| 既存の値を編集するダイアログの、フォームの初期値にする query                                                                        | loader で `queryClient.query({ ...options, staleTime: 0 })` を `staleReloadMode: "blocking"` で待つ。キャッシュの値で開くと、別のタブや別の利用者の変更より古い値でフォームが始まる (ADR-0041)                                                                                                      |

欠かせない query かどうかはページごとに、上の表の左列で決める。

## Consequences

- ページに入るとき (`enter`・`preload`)、欠かせない query の取得が遅いと、route の遷移がそれを待つ。その間は route の `pendingComponent` (無ければ ADR-0029 の既定の表示) が出る
- 副次的な query を読む部分は、ページの中で `<Suspense>` に囲む。囲まないと suspend が route の pending 表示まで巻き上がり、ページ全体が置き換わる (ADR-0029 の Context)
- 副次的な query を読む部分は、`SectionErrorBoundary` でも囲む。囲まないと取得の失敗が route の `errorComponent` まで届き、欠かせない中身ごとエラー表示に置き換わる
- 条件が変わる読み込みの失敗は、route の `errorComponent` ではなく、ページの中の `SectionErrorBoundary` に出る。再試行は境界の `reset()` で子を描き直し、`router.invalidate()` を呼ばない (`docs/guides/data-loading.md`「読み込みに失敗した画面から再試行する」)
- ページに入るときの失敗は route の `errorComponent` に出るが、その再試行 (`router.invalidate()`) は同じ location の再読み込みで `cause` が `"stay"` になるので、また失敗すると区画の中に出る。条件を変える欄はそのとき現れる
