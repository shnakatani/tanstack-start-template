# ADR-0017: 状態の通知は常時 mount の live region に集約し、項目の状態は静的テキストと `aria-busy` で持つ

- Status: Accepted
- Date: 2026-09-14
- 関連: ADR-0014 (Action 層の pending 行を本 ADR が改訂する)、ADR-0016 (行の busy 表現の読み上げを本 ADR が引き取る)、ADR-0007 (a11y の床は WCAG 2.2 AA)

## Context

pending 中の状態をスクリーンリーダーへ伝えるために、条件付きで mount される live region を 2 箇所で使っていた。

| 場所                                                      | 形                                                                                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `src/components/action/button.tsx` の `ActionButtonShell` | pending 中だけ `Spinner` (`role="status"` + `aria-label`) をボタンの子として描画する (ADR-0014「Action 層」の pending 行) |
| `src/routes/notes/index.tsx` の削除中の行と保存中の行     | 行の中に `<output>` (暗黙ロール status) で「削除中」「保存中」を置く (ADR-0016 の適用表に付けた 1 文)                     |

どちらも live region が内容ごと DOM に現れ、内容ごと消える。公式資料と先行例はこの形を避けるよう言っている。

| 出典                                                                                         | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MDN「ARIA live regions」                                                                     | 支援技術は一般に live region の内容の動的な変化だけを読む。region を先に確立してから内容を更新する。JS で挿入するなら内容の更新は後のタスクへ遅らせる。最も確実なのは初期マークアップに含めること                                                                                                                                                                                                                                                                                                                                                                                                       |
| Base UI 1.8.0 `Combobox.Status` の JSDoc                                                     | 「root 要素は DOM に mount されたままでなければ一貫して読まれない。`display: none` / `hidden` / `aria-hidden` / 条件付き描画で隠さず、children を更新するか children 側を条件付きにせよ」                                                                                                                                                                                                                                                                                                                                                                                                               |
| Sara Soueidan「Accessible notifications with ARIA live regions (Part 2)」                    | live region はページ読み込み時に挿入し、更新の前に存在させる。polite と assertive の 2 つだけを持つ。多数の region は politeness の queue で通知が失われる                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| React Aria (adobe/react-spectrum `packages/react-aria/src/live-announcer/LiveAnnouncer.tsx`) | 部品ごとの live region を持たず、`document.body` に置いた `role="log"` + `aria-live` (polite / assertive) + `aria-relevant="additions"` の region へ `announce(message)` でノードを追加し、7000ms 後に消す。region は初回の `announce()` で生成し、Safari 向けに 100ms 待ってからメッセージを入れる。React を介さず素の DOM で書く (ソースの理由は複数の React 版への互換で、本 ADR の理由とは別)。`Button` は `isPending` の切り替わりを focus 中に限り assertive で announce し (内容はボタンの名前と progress のラベル)、`useTable` は sort、`useGridSelectionAnnouncement` は選択数を announce する |
| react.dev `useSyncExternalStore` (Caveats)                                                   | 「non-blocking な Transition の更新中に store が変化すると、React はその更新を blocking として最初からやり直す」                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| APG「Feed」                                                                                  | 複数の DOM 操作の間はコンテナに `aria-busy=true` を付け、完了で false に戻す。live region には言及しない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| WAI-ARIA 1.2 `aria-busy`                                                                     | 要素が変更中であることの印。「支援技術は、その要素が所有する内容の変化を無視し、`aria-busy` が false に戻った時点で全変更を 1 つの atomic な更新として処理してよい (MAY)」                                                                                                                                                                                                                                                                                                                                                                                                                              |
| WAI-ARIA 1.2 §5.2.9 Children Presentational (`button` は True)                               | 「ユーザーエージェントはこの要素の子孫をプラットフォームの accessibility API に露出すべきでない (SHOULD NOT)」。ボタンの中の `role="status"` は露出の保証が無い (issue #21)                                                                                                                                                                                                                                                                                                                                                                                                                             |
| shadcn registry / shadcn skill と Base UI 1.8.0                                              | 相当する部品も指針も無い。`shadcn search @shadcn -q live` / `announc` / `visually` / `sr-only` は該当なし。`.claude/skills/shadcn` の SKILL.md と rules は「Button に `isPending` は無く `Spinner` + `disabled` で組む」「読み込みは `Skeleton`」までで、状態の読み上げには触れない。`node_modules/@base-ui/react` で `aria-live` を持つのは `ToastViewport` / `SliderValue` / `ComboboxStatus` / `ComboboxEmpty` の 4 つで、汎用の announcer は無い (2026-09-14)                                                                                                                                       |

条件付き mount の live region は、読まれない、または環境で挙動が揺れる。行ごとに region を作ると数が増え、通知が失われる。button の子の `role="status"` は露出の保証が無い。テーブルは live region ではないので、行の消失や追加は読み上げに出ない。

## Decision

**通知は常時 mount の live region 1 組に集約し、項目 (行やボタン) の状態は静的テキストと `aria-busy` で持つ。live region を条件付きで mount しない。**

| 対象                 | 形                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| announcer            | root layout の `RootDocument` (`src/routes/__root.tsx`、SSR され、通常画面と error 画面の両方が描く) の JSX に、空の polite と assertive の region を 1 つずつ置く (`sr-only`、`role="log"` + `aria-live` + `aria-relevant="additions"`)。初期マークアップに含めるので MDN の最上位の推奨を満たし、React Aria が region の JS 生成直後の取りこぼしに当てている 100ms の待ちが要らない。Base UI の `useInitialLiveRegionTextMutation` の 200ms は待ちではなく、mount 時に word joiner (U+2060) を足して 200ms 後に戻す text mutation で、初回 mount の読み上げを Safari VoiceOver に拾わせる細工 (2026-09-14 に `node_modules/@base-ui/react/combobox/utils/useInitialLiveRegionTextMutation.mjs` で実測)。空の region を先に置く本実装はどちらも要らない。`announce(message, politeness)` は React を介さず素の DOM でメッセージのノードを region に追加し、7000ms 後に消す (React Aria と同じ値)。React はこの region の子を描画しないので、素の DOM で子を足してよい (react.dev「Manipulating the DOM with Refs」の Best practices)。error 画面への切り替えで React が region を作り直すと追加済みのノードは消えるが、その時点の通知は error 画面が担うので許容する。実装は `src/lib/` (単体テスト付き) |
| React を介さない理由 | `useSyncExternalStore` で描くと、Action の中 (Transition の更新中) に呼んだ `announce()` が store の変化になり、React が進行中の Transition を blocking でやり直し得る (react.dev の Caveats)。React Aria も素の DOM だが、そちらの理由は複数の React 版への互換で、本 ADR とは別                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 操作の通知           | 操作の開始で「『対象』を削除しています」等を、完了で「『対象』を削除しました」等を、feature 側が polite で announce する (テーブルの行の消失・追加は読み上げに出ない)。完了の文言に対象名を載せるのは、同時に走る削除の完了が並んだときに、どちらが終わったのかを区別するため。失敗は toast (Base UI Toast、それ自体が live region) が伝えるので announce しない。完了の文言は mutation の `onSuccess` で出す。完了点 (b)/(c) (ADR-0016) では Transition の終わり (ボタンの pending 解除) より前に走り、(a) では mutation が Transition の外にあるので Transition の終了後に走る。通知の経路はこの 1 本で、部品側は announce しない (下の行)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 呼び出し層           | ドメインの文言 (「『対象』を削除しています」「保存しました」) は feature 側の mutation の `onMutate` (開始) と `onSuccess` (完了) が持って `announce()` を呼ぶ。`onMutate` は開始の通知の置き場で、キャッシュを書き換える楽観更新 (ADR-0016「楽観表示の置き場」で複数箇所のときに選ぶ方式) を採る mutation でも同じ hook に同居させる。`useActionMutation` と Action 層の部品は文言を持たず announce もしない。Action を書くときは開始と完了の announce を書くことをレビュー観点に含める (lint では検出できない)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ActionButtonShell`  | `Spinner` は視覚専用 (`aria-hidden`)。要素の状態は `aria-busy` + `aria-disabled` で持ち、focus や仮想カーソルで読まれる。部品は announce しない。React Aria `Button` は focus 中の pending の開始と終わりを assertive で announce するが、ここでは feature 側の polite な文言が同じ tick で queue に入り、assertive は queue を消してよい (ARIA の MAY、Sara Soueidan) ため、部品が出すと feature の文言のほうが消される。完了点 (a) では Action が close だけで Transition が一瞬で終わるので、部品の announce は内容も持たない。名前は `aria-labelledby` で固定したまま                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 行                   | `aria-busy` と半透明 (ADR-0016) に加え、読み順に入る静的テキスト (「削除中」「保存中」、必要なら `sr-only`) を置く。`role="status"` / `<output>` は付けない。`aria-busy=true` の間は支援技術がこのテキストの追加を無視してよいので、通知は announcer が担い、静的テキストは仮想カーソルで行を読んだときのためのものと位置づける                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 既存の region        | Base UI Toast の viewport (`role="region"` + `aria-live="polite"`、`src/routes/__root.tsx` で常時 mount) はそのまま。`TableSkeleton` (`role="status"` + `aria-busy`) は route の `pendingComponent` としてページ全体を置き換える間だけ存在する条件付き mount だが、対象は操作中の項目ではなくページ全体の置き換えで、本 ADR の対象 (操作中の項目の通知) と異なる。対象外として残す (`.claude/rules/styling.md`「状態表示」の skeleton の行)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

### 検討した選択肢

| 案                                                                  | 評価                                                                                                                                                        | 採否     |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 自前の announcer (初期マークアップに 1 組、`announce()` は素の DOM) | 依存を増やさず、MDN の最上位の推奨と Base UI `Combobox.Status` / React Aria の指針に沿う。Transition と干渉しない                                           | **採用** |
| 自前の announcer を React の store (`useSyncExternalStore`) で描く  | Action の中の `announce()` で進行中の Transition が blocking に落ち得る (react.dev の Caveats)                                                              | 却下     |
| `@react-aria/live-announcer` を入れる                               | 公式 lib だが 3.5.1 は `react-aria` (meta package) に依存する。React Aria への基盤変更は ADR-0014 で別 ADR 扱いにしており、announcer のために本体を入れない | 却下     |
| ページ側で mutation の状態から文言を導く region                     | `useMutationState` から「削除しています」を組み立てる。ボタンの Transition の pending が届かず、issue #21 を解けない                                        | 却下     |
| 項目ごとの `<output>` / 条件付き `Spinner` (ADR-0014 実装時の形)    | MDN / Base UI / Sara Soueidan の指針に反し、行数分の region が生まれる                                                                                      | 却下     |
| `aria-busy` だけで伝える                                            | 変更中の印であって通知ではない。支援技術は busy の間の変化を無視してよい                                                                                    | 却下     |
| toast で「削除しています」を出す                                    | 全員に見える通知になり、晴眼者には行の半透明で足りる情報が視覚のノイズになる                                                                                | 却下     |

## Consequences

- ADR-0014「Action 層」の pending 行を「`Spinner` は視覚専用。状態は `aria-busy` と announcer」に改訂した (Revised)。同 ADR と `src/components/action/button.tsx` の子孫 role の表現を §5.2.9 の主語 (ユーザーエージェントが露出すべきでない) に揃えた。ADR-0016 の適用表の `<output>` の 1 文を本 ADR への参照に差し替えた
- `.claude/rules/implementation.md`「accessible name の与え方」の状態表示の行と直後の箇条書きに、通知は announcer に集約する、live region は初期マークアップに置いて消さない、を足した。同節の `role="status"` を accessible name で特定する記述は、announcer の文言で検証する形に改めた。`.claude/rules/styling.md`「状態表示」の `Spinner` の行に視覚専用 (`aria-hidden`) を添えた
- テストは `getByRole("status", { name })` で項目の pending を掴む形をやめ、`aria-busy` と announcer の region のテキストで検証する
- issue #21 (button 内の `role="status"` の露出) の対処は本 ADR で行う。実機のスクリーンリーダー (VoiceOver / NVDA) での読み上げ確認は #21 に残し、結果を本 ADR に日付付きで追記する
- 削除完了で行ごと unmount されるとき、行のトリガーにあったフォーカスが body へ落ちる。ADR-0014 実装時からある事象で、本 ADR は完了の announce で通知は補うが、フォーカスの退避先は別途決める (起票)
- 再評価条件: Base UI か shadcn が announcer を出荷したら差し替える。React Aria へ基盤を変えるなら `announce` をそちらへ寄せる
