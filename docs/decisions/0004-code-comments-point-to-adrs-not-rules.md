# ADR-0004: ソースと設定のコメントは rules ではなく ADR を指す

- Status: Accepted
- Date: 2026-09-23
- 関連: ADR-0001 (規範・経緯・履歴の置き場所) / ADR-0000 (番号を使い回さない)

## Context

ソースと設定のコメントは、その形を選んだ理由を出典で示すことがある。
出典の候補は `.claude/rules/` の見出しと `docs/decisions/` の ADR の 2 つである。

このリポジトリはテンプレートとして配布される。
利用者は `.claude/rules/` を自分のプロジェクトの規範に合わせて書き換え、差し替える。
rules の見出しは編集で変わり、変わっても参照側は静かに宙に浮く。
ADR は番号で指し、番号は使い回さない。決定が置き換わっても、旧 ADR は置き換え先を示して残る (ADR-0000)。

## Decision

**ソース (`src/`、`scripts/`) と設定ファイル (`vite.config.ts`、`vitest.config.ts` など) のコメントが理由の出典を示すときは、`ADR-NNNN` で ADR を指す。`.claude/rules/` のファイル名や見出しは指さない。**

- 理由を持つ ADR が無いときは、コメント自身に理由を書き、出典を付けない
- rules から ADR を指すのはよい。rules は規範 1 行と出典キーを持つ場所で、指す向きは rules → ADR になる

### 検討した選択肢

| 案                                   | 評価                                                                                       | 採否     |
| ------------------------------------ | ------------------------------------------------------------------------------------------ | -------- |
| ADR を番号で指す                     | 利用者が rules を差し替えても参照先が残る。決定が変わっても旧 ADR から置き換え先を辿れる   | **採用** |
| rules の見出しで指す                 | 規範の現在の文面に近いが、見出しの編集と利用者の差し替えで行き先が消え、消えても気づけない | 却下     |
| コメントに理由を書き、出典を付けない | 行き先が消えることは無いが、選択肢の比較と却下理由までは書けず、ADR との二重管理になる     | 却下     |

## Consequences

- コメントから rules へのリンクを張らないので、コメントを読んだ人が現在の規範の文面を知るには、ADR を読んだうえで rules を探す
- ADR を分割したら、コメント中の `ADR-NNNN` を内容で振り分け直す。参照は `git grep -n "ADR-NNNN"` で拾える
