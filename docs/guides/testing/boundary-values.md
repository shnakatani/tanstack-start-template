# 境界値のテスト

上限や切り詰めのような境界を持つ処理のテストで、確かめる点と期待値の書き方を持つ。

## how-to

### 境界値を確かめる

- 上限 (cap) を持つ処理は、`cap - 1`、`cap`、`cap + 1` の 3 点で確かめる。実例は `src/lib/truncate-code-points.test.ts`。各点が押さえるものは「境界の前後を 3 点で見る理由」
- 期待値を導く数式を、期待値の前にコメントで書く (例: `// 900 + 200 = 1100 → slice(-1000) で先頭 100 件破棄`)。読み手は数式を検算して、期待値が正しいかを確かめられる

## explanation

### 境界の前後を 3 点で見る理由

3 点は、上限の手前、上限ちょうど、上限の先をそれぞれ 1 点ずつ押さえる。

| 点        | 確かめること                   |
| --------- | ------------------------------ |
| `cap - 1` | 上限の手前では処理が変わらない |
| `cap`     | 上限ちょうどの扱い             |
| `cap + 1` | 上限を超えた分の扱い           |

- 比較の取り違えは、向きによって片方の点にしか現れない。`<=` と書くべき比較を `<` と書くと `cap` で、`<` と書くべき比較を `<=` と書くと `cap + 1` で落ちる
- `cap - 1` は、上限ちょうどを特別に扱う分岐があっても、その手前が通常の扱いのままであることを押さえる

### 期待値の数式をコメントに書く理由

期待値を数式から書くと、実装を走らせて出た値を写した期待値と区別が付く。実装の出力を期待値に写すと、実装の誤りがそのままテストの正解として固定され、テストは実装と一緒に誤ったまま通る。数式がコメントにあれば、レビューで数式と期待値を突き合わせられる。
